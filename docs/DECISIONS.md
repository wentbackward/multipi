# Decisions

Decisions the dev loop made where the spec was silent. Newest last.
One line each: `YYYY-MM-DD — decision — why — alternatives considered`.

- 2026-10-27 — Install layout: `install.sh <repo>` copies scripts/ (versioned in the target), the extension to `.pi/extensions/multipi-devloop/` (self-contained, with an `agents/` copy for the bundled-dir fallback), roles to `.pi/agents/` (project layer, shadows bundled), skills to `.pi/skills/`. Targets become self-contained and re-install is a sync; a pi-package distribution is deferred — copy semantics beat a publish channel for a tool this young.
- 2026-10-27 — Extension contexts are built lazily per tool invocation from the tool context's cwd (guarded: a repo without `.devloop.json` gets a clear error result, not a crash). pi's ExtensionAPI exposes no cwd at registration time, and orchestrators may serve more than one repo — a context frozen at load was wrong by construction.
- 2026-10-27 — Added `MULTIPI_AGENTS_DIR` env override for the bundled role-prompts directory (alongside `MULTIPI_PI_BIN`, `MULTIPI_HOME`, `MULTIPI_LOCK_DIR`). Unit tests must steer role discovery without touching the packaged dir; the same seam lets a user point at shared prompts.
- 2026-10-28 — The batch gate reads `.devloop.json` from the MAIN repo root, not from the stacked worktree (common.sh: DL_CONFIG = $DL_ROOT/.devloop.json). Security property: a gated branch cannot redefine or weaken the check set that validates it. Consequence: a branch that ADDs a check (e.g. the hygiene suite in #3) gets that check running at the gate only AFTER it lands on main — the gate result in the meantime covers the base check set, which is the strongest set the base can vouch for.
- 2026-10-27 — Review findings are posted as issue COMMENTS and the implementer brief carries the latest comment verbatim (plus step 2 mandates reading comments). Observed live: a resumed child validated correctly but skipped a must-fix it never saw; the ticket body alone is not the communication channel.
- 2026-10-27 — `addLabel` self-heals: if GitHub reports the label missing it runs `gh label create --force` and retries once, so a managed repo never needs label pre-creation and the loop cannot stall on first use. The alternative (documented pre-creation in setup only) left the loop brittle against label renames/deletion.
- 2026-10-27 — `issues.ts` parses `gh --json` output format-agnostically (`parseGhOutput`, unit-tested): gh has been observed to emit a single compact JSON array AND NDJSON depending on version/count; the code accepts both, and the fake keeps NDJSON so the fallback path stays exercised.
- 2026-10-27 — Dispatch persists the dispatch-state entry BEFORE spawning the child and `git fetch`es after it finishes; refusal order is busy-ticket, then capacity, then ticket lookup (local facts before remote ones). Cancel then always finds what it kills, and the main repo's remote-tracking refs are fresh when the PR step runs.
- 2026-10-27 — Role tool grants: implementer gets pi's DEFAULT tool set (omit `tools:`); code-reviewer gets `read, grep, find, ls, bash` (runs tests but never commits); verifier gets the same minus commit ability by virtue of the same grant plus its read-only prompt. Granting implementer `read, bash` would have broken the actual implementing.
- 2026-10-27 — `fake-pi` (ok mode) behaves like an honest implementer: writes the notes file its brief names, commits one change, pushes the branch. This lets the FULL dispatch→PR→label pipeline be tested offline; the fake stays a fake (no LLM) and documents its limits in its header.
- 2026-10-27 — Stop-gate counter lives in the repo's git common dir (`devloop-stop-count`), never committed; the loop-drive branch (startable ticket + free slot) is unbounded by design and must NOT bump the bounded counter — a red fast check and a dirty tree are bounded (`stop_gate.max_blocks`, then reset + settle) so the agent can never wedge.
- 2026-10-27 — Format-on-edit uses plain suffix matching for `format_extensions` (".ts" does not cover ".tsx"); the config schema comment and the setup skill both say list every distinct extension. Suffix-with-boundary matching was rejected as a second mental model for a one-line rule.
- 2026-10-27 — `make check` stays fully offline (smoke + tsc + node tests + shellcheck). A live `pi` load probe needs API access and is therefore a manual step (run one `devloop.status` in a fresh session), not a CI gate.
- 2026-10-28 — `make shellcheck` runs from inside `scripts/` (`cd scripts && shellcheck *.sh lib/*.sh ../tests/fake-gh ../tests/fake-pi`) so the `$scripts_dir/lib/common.sh` dot-sources resolve to an input file and are followed; shellcheck 0.11.0 resolves variable-containing source expressions CWD-relative, so neither the existing `# shellcheck source=lib/common.sh` directives nor adding the lib as a CWD-mismatched input suppressed SC1091 when invoked from the repo root (verified empirically). Chosen over `disable=SC1091` (silencing, no analysis) and over rewriting the source to `$(dirname …)/scripts/lib/common.sh` (fragile, dir-name dependent); a planted violation in `lib/common.sh` is caught, proving the lib is genuinely analysed. `tests/fake-gh` lists issues with `find -mindepth 1 -maxdepth 1 ! -name '.*' -printf '%f\n' | sort -n` instead of `ls` (SC2012); numeric-ordering behaviour is guarded by `tests/hygiene.sh`, now part of `make check`.
- 2026-10-28 — The batch gate reads checks from `.devloop.json`, not `make check`; `tests/hygiene.sh` now asserts the hygiene entry exists there (command + non-heavy), so the suite can never again be invisible to the gate. Chosen over documenting the coupling in AGENTS.md (tests enforce, prose decays).
- 2026-10-28 — SC2027/SC2140 from the fake-gh comment feature (line with the `comments=` JSON) were triaged in gate round 1 as "fixed at loop level" but had not landed on origin/main when ticket #3 was re-dispatched, and ticket AC #1 requires `make shellcheck` exit 0 — fixed inline in this branch by collapsing the word to one double-quoted string with escaped quotes (`"{\"body\":\"$(jesc …)\"}"`); output is byte-identical (probe with embedded quotes + newlines). If the loop-level fix also lands on main, expect a trivial 1-line rebase conflict in the gate — resolve by keeping any one form; both satisfy shellcheck.
