# Decisions

Decisions the dev loop made where the spec was silent. Newest last.
One line each: `YYYY-MM-DD — decision — why — alternatives considered`.

- 2026-10-27 — Install layout: `install.sh <repo>` copies scripts/ (versioned in the target), the extension to `.pi/extensions/multipi-devloop/` (self-contained, with an `agents/` copy for the bundled-dir fallback), roles to `.pi/agents/` (project layer, shadows bundled), skills to `.pi/skills/`. Targets become self-contained and re-install is a sync; a pi-package distribution is deferred — copy semantics beat a publish channel for a tool this young.
- 2026-10-27 — Extension contexts are built lazily per tool invocation from the tool context's cwd (guarded: a repo without `.devloop.json` gets a clear error result, not a crash). pi's ExtensionAPI exposes no cwd at registration time, and orchestrators may serve more than one repo — a context frozen at load was wrong by construction.
- 2026-10-27 — Added `MULTIPI_AGENTS_DIR` env override for the bundled role-prompts directory (alongside `MULTIPI_PI_BIN`, `MULTIPI_HOME`, `MULTIPI_LOCK_DIR`). Unit tests must steer role discovery without touching the packaged dir; the same seam lets a user point at shared prompts.
- 2026-10-28 — The batch gate reads `.devloop.json` from the MAIN repo root, not from the stacked worktree (common.sh: DL_CONFIG = $DL_ROOT/.devloop.json). Security property: a gated branch cannot redefine or weaken the check set that validates it. Consequence: a branch that ADDs a check (e.g. the hygiene suite in #3) gets that check running at the gate only AFTER it lands on main — the gate result in the meantime covers the base check set, which is the strongest set the base can vouch for.
- 2026-10-27 — Review findings are posted as issue COMMENTS and the implementer brief carries the latest comment verbatim (plus step 2 mandates reading comments). Observed live: a resumed child validated correctly but skipped a must-fix it never saw; the ticket body alone is not the communication channel.
- 2026-10-27 — `addLabel` self-heals: if GitHub reports the label missing it runs `gh label create --force` and retries once, so a managed repo never needs label pre-creation and the loop cannot stall on first use. The alternative (documented pre-creation in setup only) left the loop brittle against label renames/deletion.
- 2026-10-27 — `issues.ts` parses `gh --json` output format-agnostically (`parseGhOutput`, unit-tested): gh has been observed to emit a single compact JSON array AND NDJSON depending on version/count; the code accepts both, and the fake keeps NDJSON so the fallback path stays exercised.
- 2026-10-27 — Dispatch persists the dispatch-state entry BEFORE spawning the child and `git fetch`es after it finishes; refusal order is busy-ticket, then capacity, then ticket lookup (local facts before remote ones). Cancel then always finds what it kills, and the main repo's remote-tracking refs are fresh when the PR step runs.
- 2026-10-27 — Role tool grants: implementer gets pi's DEFAULT tool set (omit `tools:`); code-reviewer gets `read, grep, find, ls, bash` (runs tests but never commits); verifier gets the same minus commit ability by virtue of the same grant plus its read-only prompt. Granting implementer `read, bash` would have broken the actual implementing.
- 2026-10-27 — `fake-pi` (ok mode) behaves like an honest implementer: writes the notes file its brief names, commits one change, pushes the branch. This lets the FULL dispatch→PR→label pipeline be tested offline; the fake stays a fake (no LLM) and documents its limits in its header.
- 2026-10-27 — Stop-gate counter lives in the repo's git common dir (`devloop-stop-count`), never committed; the loop-drive branch (startable ticket + free slot) is unbounded by design and must NOT bump the bounded counter — a red fast check and a dirty tree are bounded (`stop_gate.max_blocks`, then reset + settle) so the agent can never wedge.
- 2026-10-27 — Format-on-edit uses plain suffix matching for `format_extensions` (".ts" does not cover ".tsx"); the config schema comment and the setup skill both say list every distinct extension. Suffix-with-boundary matching was rejected as a second mental model for a one-line rule.
- 2026-10-27 — `make check` stays fully offline (smoke + tsc + node tests + shellcheck). A live `pi` load probe needs API access and is therefore a manual step (run one `devloop.status` in a fresh session), not a CI gate.
- 2026-10-28 — `make shellcheck` runs from inside `scripts/` (`cd scripts && shellcheck *.sh lib/*.sh ../tests/fake-gh ../tests/fake-pi`) so the `$scripts_dir/lib/common.sh` dot-sources resolve to an input file and are followed; shellcheck 0.11.0 resolves variable-containing source expressions CWD-relative, so neither the existing `# shellcheck source=lib/common.sh` directives nor adding the lib as a CWD-mismatched input suppressed SC1091 when invoked from the repo root (verified empirically). Chosen over `disable=SC1091` (silencing, no analysis) and over rewriting the source to `$(dirname …)/scripts/lib/common.sh` (fragile, dir-name dependent); a planted violation in `lib/common.sh` is caught, proving the lib is genuinely analysed. `tests/fake-gh` lists issues with `find -mindepth 1 -maxdepth 1 ! -name '.*' -printf '%f\n' | sort -n` instead of `ls` (SC2012); numeric-ordering behaviour is guarded by `tests/hygiene.sh`, now part of `make check`.
- 2026-10-28 — The batch gate reads checks from `.devloop.json`, not `make check`; `tests/hygiene.sh` now asserts the hygiene entry exists there (command + non-heavy), so the suite can never again be invisible to the gate. Chosen over documenting the coupling in AGENTS.md (tests enforce, prose decays).
- 2026-10-28 — SC2027/SC2140 from the fake-gh comment feature (line with the `comments=` JSON) were triaged in gate round 1 as "fixed at loop level" but had not landed on origin/main when ticket #3 was re-dispatched, and ticket AC #1 requires `make shellcheck` exit 0 — fixed inline in this branch by collapsing the word to one double-quoted string with escaped quotes (`"{\"body\":\"$(jesc …)\"}"`); output is byte-identical (probe with embedded quotes + newlines). If the loop-level fix also lands on main, expect a trivial 1-line rebase conflict in the gate — resolve by keeping any one form; both satisfy shellcheck.
- 2026-10-28 — doctor's extension-runtime check probes resolution with Node's own resolver (`await import(<pkg>)` from the repo root) instead of a `node_modules/<pkg>` file-existence test — a half-installed or corrupt package fails exactly as pi would see it at load. File existence was rejected as weaker.
- 2026-10-28 — The check runs whenever `.pi/extensions/multipi-devloop/` exists, independent of `.devloop.json` presence, so a half-set-up repo reports the config gap and the runtime gap in one run; when node itself is absent, only `node` is named (packages are unverifiable without it). Config-gated placement was rejected (runtime problems would stay hidden).
- 2026-10-28 — doctor reports a crashed extension-runtime probe as its own MISSING line instead of an ok line — a dead probe verifies nothing, and a diagnostic must never claim health on unproven input; treating the probe as simply failed was rejected as indistinguishable from a real miss.
- 2026-10-28 — doctor's runtime probe now runs from `.pi/extensions/multipi-devloop/` (pi's actual resolution context, fixing a false negative for packages resolvable from the extension dir but not the repo root) and silences stdout while each dependency is imported; bash then counts only lines that exactly match the two known package names as missing, and any other line OR a non-zero probe exit becomes the `extension runtime probe` MISSING line on top of the genuinely named misses. Unfiltered probe stdout was rejected (review round 2: a `console.log` in a dependency spawned a fake `MISSING` package and masked a real crash); probing from the repo root was rejected as diverging from pi's lookup.
- 2026-10-28 — Implemented the optional third parked item from #1 alongside the wording fix: the smoke no-node PATH surgery no longer expands unquoted `${PATH//:/ }` with hardcoded /usr/bin,/bin,/usr/local/bin globs; it splits PATH quoted (IFS read -ra), filters node-bearing dirs, and re-provisions a named tool list (env bash sh git jq python3 cut dirname basename realpath mkdir) derived from `command -v`. The brittle case got robust instead of merely patched; a literal list was chosen over re-globbing because doctor, common.sh and fake-gh have a small, auditable runtime footprint, and the test itself is the audit.
- 2026-10-29 — The ANALYST role decomposes specs (and operator feedback in focus mode) into ordered ticket plans; the ORCHESTRATOR raises the issues from the plan. Alternatives rejected: (a) analyst creates issues itself — an unattended child defining scope is exactly the failure mode the loop exists to prevent, and ticket creation must be one auditable component; (b) orchestrator writes plans itself — its context is the whole loop, not deep in the spec, and a fresh read-only child is cheaper and less biased.
- 2026-10-29 — Analyst disposition matches the verifier (no ticket, no capacity slot, repo-root, read-only); key `analyst-<slug>` so re-analysis reuses state and concurrent same-spec analyses are refused busy. The plan lands in the notes dir AND in the report so the dispatch return is self-sufficient.
- 2026-10-29 — Child processes run with MULTIPI_CHILD=1 (set by spawnPi) and the extension registers NOTHING for them (index.ts guard). Observed live: an analyst child that had delivered its plan at minute 7 kept running 30+ minutes because it loaded the project extension and sat in the stop-gate's "startable ticket + free slot" continue loop; worse, the tools would have let a child dispatch grandchildren. Children are executors; only the orchestrator drives. Alternatives rejected: per-child env disabling just the hook (tools are the real hazard); detecting "am I a child" heuristically (env is deterministic, heuristics rot).
- 2026-10-29 — Every gh call pins `--repo <owner/name>` derived from the configured remote (repoSlugFromRemote). gh resolves to the PARENT tracker inside a fork — observed live: the crisis fork's analyst (and a session before it) read PGALLC's upstream issue tracker (issues 18-47) as if it were the fork's board, and two phantom implementer dispatches chased upstream tickets. Alternatives rejected: deleting the `upstream` remote (useful for pulling); trusting gh's detection (it is right 90% of the time, which is 100% the wrong number for a loop).
- 2026-10-29 — Children stream progress: spawnPi accumulates turns/tokens/cost/current-activity from the NDJSON stream and emits tool updates — every completed turn (forced) plus a 30 s heartbeat, 20 s rate-limited while events flow — rendered as `[role mm:ss · tok 123k · $1.23 · bash: npm test]`. Users watching a blocked devloop.dispatch see where the child is and what it has cost; the final report still carries the authoritative totals. Alternatives rejected: no telemetry (the observed 30-minute opaque wait is the bug); per-delta streaming (floody, costs nothing extra in signal).
- 2026-10-29 — Agent visibility lives in the TUI via a below-editor widget (one line per running child) and a /devloop-agents browse panel; both render from an IN-PROCESS registry (childreg.ts) fed by spawnAndTrack, not from the state file — children run in the orchestrator's process, so their live progress is directly observable and the state file stays the durable end-state record. The registry is bounded (40-event ring per child, 8 finished entries) because it is UI data, not truth. Rendering is pure (renderChildBar / renderAgentsPanel, unit-tested incl. width truncation and the scroll window); index.ts holds only the thin pi-TUI glue. Alternatives rejected: polling the state file (end-states only — no live data, and file churn for UI); a separate watcher process (extra lifecycle to kill; the data is already in-process).
- 2026-10-29 — `devloop.pause` is an explicit operator checkpoint, distinct from `devloop.cancel` (one child) and from Ctrl+C (kills everything, no record). It (1) SIGTERMs every running child, keeping worktrees/branches; (2) writes `HANDOFF.md` to the notes dir — per-child positions (ticket, branch, elapsed, HEAD, dirty count) + the open-board snapshot at that instant; (3) comments each interrupted ticket with a one-line operator note. Resume is a fresh session: skill step 0.3 reads the handoff and re-dispatches the listed children (same ticket -> same worktree). Chosen over a state-file flag (the handoff is a human-readable record that survives tooling changes, and the board snapshot is what an operator actually needs to reason about); chosen over auto-pause-on-idle (an idle loop is legitimate work, and pause must be a deliberate act). buildHandoff is pure and unit-tested; the kill is bounded-wait (15 s) and reports laggards instead of silently claiming success.
- 2026-11-01 — Watchdog = stream silence, not wall time: a child emitting no output for `child_silence_minutes` (config, default 30) is killed as a whole process tree (SIGTERM, SIGKILL after 15 s), recorded crashed with `WATCHDOG: …` in errorMessage and exitCode 124, and re-dispatched by the ordinary crashed-entry recovery. Chosen over per-tool-call timeouts (a single long bash call is legal; the event stream is the only honest progress signal we observe) and over a wall-clock cap (a chatty 4-hour child is healthy). The poll interval scales with the threshold so tests use sub-second values without a 10 s tick.
- 2026-11-01 — Children spawn `detached` (own process group, pgid == child pid) so abort/cancel/pause/watchdog all kill the GROUP, and every child exit sweeps the group for survivors (SIGTERM → SIGKILL after 5 s, count reported). An orchestrator `exit` hook SIGKILLs any still-live child tree. The hard-kill limitation (SIGKILL of the orchestrator bypasses hooks) is accepted: that residue is exactly what step-0 recovery is for. Windows degrades to single-process kills (CAN_PGID guard) — Linux/macOS are the supported loop platforms.
- 2026-11-01 — spawnPi settles on the child's `exit` event, not `close`: a leaked grandchild (an abandoned browser) inherits the child's stdio and holds the write ends open, so `close` would never fire while the child is long dead — discovered live: the orphan-reaping test deadlocked the whole suite until the settle was moved to `exit` (with `close` as fast path and a 150 ms post-exit fallback for buffered tail data). Settling on `close` was the natural choice and exactly the wrong one for the failure this feature exists to catch.
- 2026-11-01 — External-session commit 8dcf57c (GH_REPO pin in common.sh, made by a second session testing the loop) left `dl_load_config` returning 1 whenever GH_REPO was empty: its last line `[ -n … ] && export` is a failing conditional, and every `&&` caller in the offline smoke fixtures broke — the second session's gate then looped red on its own commit. Fixed with an unconditional `return 0` (both the plugin source and the per-repo crisis copy, which carries the same block per its sync NOTE) rather than reverting the pin, whose intent (fork-trap proof at the script level) matches the extension's `--repo` pinning.
- 2026-11-01 — Review entries are classified on the REVIEWER's contract (VERDICT: APPROVE/CHANGES → done; no verdict → crashed), not the implementer's STATUS contract. Observed live in two projects: every successful review (full reports, stopReason=stop) was recorded "crashed" because finishEntry only knew STATUS: DONE — the loop survived because the orchestrator reads the report text, but the state file and every consumer of it lied, and 70 entries needed reclassification (reviewed VERDICT-bearing reports were flipped to done in both state files). A report that lacks the role's contract marker stays "crashed": that IS a contract violation.
- 2026-11-01 — Worktrees get a consolidated home and a lifecycle owner. `worktree_dir` (default `~/.multipi/<repo>/worktrees/<repo>`) holds ALL issue worktrees plus the gate worktree, so a project contributes one entry to its parent directory instead of one folder per ticket (observed live: 35+ siblings littering ~/hacking). devloop.merge removes the worktree of each merged branch when clean — the loop that created a worktree owns its deletion; a DIRTY worktree is kept with a loud note, because uncommitted work is evidence, never clutter. `scripts/cleanup-worktrees.sh` collects pre-existing litter under the same guards (clean + branch gone from remote + not the gate/main worktree); it is a collector, not a bulldozer — everything else is listed as KEPT with a reason.

- 2026-11-05 — Dark-factory spec amended at pre-implementation review (four pinned-contract fixes, operator-approved): (1) the sealed-checksum is now PINNED — `int(first 10 hex chars of sha256(id), 16) mod 1000 < sealed*1000` — the spec's bare `checksum(id)` was platform/algorithm-ambiguous and would let the seal (and thus which scenarios are hidden) drift; (2) the role guard learns the store path by reading `.devloop.json` from the child's working dir at extension load, with NO env seam carrying it (env is child-readable; the path was never secret — it is in the committed config — the hook denies ACCESS, not knowledge) and fails CLOSED if the path is unresolvable; (3) the VERIFIER is added to the guarded roles — it runs at repo root post-merge and its reports reach the implementer, so unguarded it could read the store and launder it through its report; (4) judges are spawned by the stage script itself exec'ing the `pi` binary detached (own group, TERM→KILL), mirroring the spawnPi/watchdog spawn contract — a bash script cannot import the TS `spawnPi`, and the earlier wording implied it could.
- 2026-11-01 — Dark-factory spec authored (docs/superpowers/specs/2026-11-01-multipi-dark-factory.md), porting claude-dev-loop 0.7's migration (epic #2) to multipi's architecture. Three pi-native adaptations pinned: (a) the role guard rides the child-isolation seam — a child of a guarded role (implementer, code-reviewer) loads a GUARD-ONLY extension mode (one block-capable tool_call hook, nothing else) keyed on the new MULTIPI_CHILD_ROLE env; a child can still register no tools, the isolation guarantee is unchanged; (b) the scenario stage's run command reuses the watchdog's detached-spawn/process-group machinery (own group, first line = target, TERM->KILL teardown); (c) judges are ordinary one-shot headless children via spawnPi with MULTIPI_SCENARIO_FILE/ID/TARGET env — the script decides green/red, never the agent, matching every other multipi gate contract. Sealed scenarios keep the reference's deterministic rule (checksum(id) mod 1000 < sealed*1000): stable, stateless, no agent discretion.
- 2026-11-05 — Config layer gains `factory` and `scenarios` (dark-factory spec §1/§2): `factory` accepts only `"dark"` verbatim, any other value (typo, null, garbage) coerces to the `"collaborative"` default — matching the config layer's existing default-coercion discipline (str/num/bool helpers); failing the whole parse for a preset typo would brick the loop over a readability device. A `scenarios` value that is neither an object nor `false` (null, array, string) parses as ABSENT, so presence/absence semantics stay meaningful; only a JSON object counts as "the block" and an explicit `false` is the only off-switch. Alternatives: reject the config outright on bad `factory` (too harsh for a preset), or trim unknown `scenarios` shapes to `{}` (would silently turn the store ON — dangerous direction).
- 2026-11-05 — Latent bug found while writing the `scenarios.dir` smoke test: the absolute/`~/` detector in `dl_worktree_dir` (`${wd#~/} != $wd`) never fires for `~/` values — in bash the unquoted `~` inside a `${var#pattern}` undergoes tilde expansion to `$HOME/`, so the pattern cannot match and a `worktree_dir: "~/x"` silently resolved against the repo PARENT as `../~/x`. Fixed in both `dl_worktree_dir` and its mirror `dl_scenarios_dir` by quoting the tilde in the pattern (`${wd#"~"/}`); both now match the documented "absolute, ~/, or relative-to-PARENT" rule, pinned by new smoke expects.
